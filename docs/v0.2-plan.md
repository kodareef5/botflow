# v0.2 plan: manager maturity

Five workstreams, in build order. UI foundation ships first ("polish before spending more"); everything after rides on it.

## 1. UI de-slop: foundation first

What's sloppy today, honestly: ad-hoc px values with no rhythm, `prompt()` dialogs for create flows, full-innerHTML rerenders (scroll loss, flash), emoji as icons, crowded header, no focus states or aria, default-looking rounded-card sameness, and the viewer + manager duplicating drifting UI code.

The fix is a small real design system, hand-rolled and zero-dep:

- **Tokens** (`worker/src/ui/tokens.ts`, single source, consumed by manager *and* later the local viewer):
  spacing on a 4px grid; type ramp 12/13/14/16/20 with one mono role; per-style radius, border weight, shadow level, density; color tokens per style × mode × accent.
- **Components** (each with hover/focus/active/disabled states, aria roles):
  AppShell (header / sidebar / content), LaneColumn (sticky header, equal heights), Card (fixed anatomy: id+state row → title → meta row), StateChip, Meter, DistributionStrip + count chips, DataTable, Drawer (as `role=dialog`, focus-trapped), **Modal forms replacing every `prompt()`**, EmptyState (with a next-step action), Toast, Tabs, inline-SVG icon set (kills the ⛔/▶ emoji).
- **Interaction**: DOM patching that preserves scroll/focus on poll refresh; Esc everywhere; visible focus rings; `?` no: keep it minimal: Esc, tab order, drawer deep-link.
- **Gate**: every screen screenshot-reviewed light + dark before ship; palette validator re-run on any color change.

## 2. Themes: 5 styles, admin-selectable

A style is more than a palette: it sets radius, border weight, density, type, shadows. All five share the same components and structure; tokens do the differentiation. Each ships **light + dark + at least one alternate accent**, every combination run through the CVD/contrast validator (results recorded in tokens.ts comments).

| Style | Vibe | Alt accent |
|---|---|---|
| **Reef** *(default)* | today's calm neutral, soft radius | Lagoon (teal) |
| **Phosphor** | terminal: mono, dense, hairlines, square corners; dark = green-on-black | Amber |
| **Papercut** | warm paper, ruled-index-card borders; dark = charcoal paper | Red-pen |
| **Mochi** | soft, plush, 12px radius, pastel accents, gentle shadows | Ume (plum) |
| **Bricks** | neobrutalist: 0 radius, thick borders, hard offset shadows, loud | Taxi (yellow) |

Admin **Settings** section (new sidebar entry): style picker with live preview tiles, accent picker, default mode (system/light/dark). Stored org-wide in the registry; visitors' OS mode still respected; per-user mode override in localStorage. Public share pages render in the org's chosen style.

## 3. Nesting: projects are projects; projects can be cards

Drop the idea of a separate hierarchy mechanism. One mechanism, same as the file spec:

- A sub-project is created by adding a **project card** (`type: board`) to the parent project's board. The card's reference is `board: project:<id>`: a new recognized reference scheme beside relative paths (SPEC §3 note; file-side, `project:` refs lint as info, not error).
- The sidebar "+ sub-project" button becomes sugar: create project → drop its project card into the parent board (default lane `todo`). The card is the truth for rollup; the registry keeps a flat project list (auth/routing) plus a derived tree for the sidebar.
- **Hosted rollup becomes real**: ProjectDO resolves `project:` cards by asking sibling DOs for their distributions: the parent's board now rolls up exactly like the file engine, and the "unresolved board-card" limitation dies.
- **Nesting depth: let them go.** Unlimited, with a visited-set passed through DO calls; a cycle degrades to the card's own lane (same as the file engine's `board-cycle` behavior). UI indentation caps visually, not structurally.
- Archiving the project card removes the child from the parent's rollup without deleting anything.

## 4. Sharing & admin controls

**Recommendation: capability URLs, not public flags.** An unguessable revocable link beats a boolean "space is public": no crawler surface, per-audience revocation, and it composes at any level.

- Share scopes: **project board** (read-only board, drawer, optional activity toggle) and **single card** (card + log only). Space-level sharing = share the projects you mean; not a v0.2 feature.
- URL: `/s/<token>`; card deep-link `/s/<token>?card=001`. Rendered in the org's theme with a small "powered by botflow → GitHub" footer (same growth loop as the gate).
- Registry gains a `shares` table (token hash, scope, project/card, created, last_viewed, revoked) and: overdue: a **registry audit log** (project created, key minted/revoked, share created/revoked, settings changed, admin rotated).

**Admin controls inventory (v0.2):** rename company · style/theme settings · **admin token rotation** (mint new, kill old) · recovery reset via a `wrangler secret` (`ADMIN_RESET_KEY`) for the lost-token case · spaces: create/rename/archive · projects: create/rename/archive (delete stays off the menu; archive is the safe verb) · keys: mint/revoke + last-used stamp · shares: create/revoke/list · org-level activity view.

## 5. Board redesign tools

Admin board editor (a "design" tab on each project):

- **Lanes**: add, rename, reorder, remove; per lane: display name, **canonical mapping (required, dropdown of the six: the editor cannot produce an unmapped lane, which is how "mapping back to the aggregate basics" stays guaranteed)**, ordered substates, strict/free, WIP limit.
- **Rollup policy**: the four knobs (`blocked_when / done_when / doing_when / else`) with a plain-English preview ("this board reports *blocked* upward while any child is blocked").
- **Guardrails**: removing or renaming a lane that holds cards forces a destination choice; every migrated card gets a Log entry; the whole edit is one DO transaction + one audit event.
- **Presets** at project creation: *basic six*, *review-gated* (strict `doing: build → review`), *triage* (specialty intake lanes → todo).
- Mechanics: UI form → validated config → `updateConfig(yaml, laneMigrations)` RPC. UI edits re-emit YAML, so hand-written comments in a pushed board.yaml are lost on first UI edit: documented tradeoff.
